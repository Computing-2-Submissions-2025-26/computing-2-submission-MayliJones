Methods

evaluate_wall(state, orientation, r, c) → {string}

Description:

  • Shared by legal_moves and wall_placement_reason: does a wall at (r, c) with this orientation overlap an existing wall, and if not, does placing it still leave both players a path to their goal? Checks overlap first since it's cheap - only runs the path check (two BFS calls) if there's no overlap.
